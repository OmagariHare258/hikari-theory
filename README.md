# 橘小光理论（一份关于 LLM 角色长期运行方式的整理）

这个仓库是我个人在搭 QQ 角色过程中整理的笔记，主要记两件事：角色卡怎么写才比较稳，以及桥接层怎么做才不容易出问题。

内容来自我自己的一套环境（DSH + SurfCore + SnowLuma），换环境需要相应调整。依赖特定版本的做法我会标出来。

示例角色用的是《蔚蓝档案》的橘光，但它只是参考样本；你可以用自己的角色卡，或者直接描述一个角色，方法本身不绑定具体角色。

---

## 它能解决什么

常见的几类问题：

- 聊十句像人，聊到第三天开始像客服；
- 说话爱堆设定名词、爱背原作台词；
- 换模型、重置会话、接新平台之后，状态接不上；
- 长时间挂机偶尔会卡住，或者某个群突然不理人；
- 想加语音、发图、跨群转述时，工具层容易出各种小问题。

这些问题有些在人格卡，有些在表达规则，有些在桥接进程。这个仓库按层把它们拆开处理：人格、状态、关系、表达、素材、工程底座。拆开之后改一层基本不会连带弄坏别的层。

SurfCore 本身已经把 QQ 接入、会话调度、唤醒、发送这些主干做得比较完整。我的改动主要集中在角色侧调细和边界情况处理上。

## 给 AI 的安装入口

如果这台电脑只装了 DSH，可以把仓库地址直接发给它，并说：

> 读 https://github.com/OmagariHare258/hikari-theory 的 AGENTS.md，按里面的阶段帮我搭。需要我登录、扫码、给 token 的时候停下来问我。

仓库里给 AI 准备了这些东西：

- **AGENTS.md**：阶段 0–8 的执行流程，每阶段有验证条件和失败处理；明确写了哪些必须问人、哪些不能猜。
- **BOOTSTRAP.md**：人这边的清单（系统、QQ 号、SnowLuma 登录、模型 key、验收）。
- **scripts/bootstrap.ps1**：能自动的部分——检查环境、拉 SurfCore、复制补丁文件、尝试打补丁、装依赖、生成配置骨架。
- **VERSIONS.md**：补丁对应的上游版本，避免拉错版本。

自动部分可以先跑：

```powershell
pwsh -File scripts/bootstrap.ps1
```

跑完会打印剩余的人工步骤。QQ 登录、扫码、短信验证这些环节没法自动化，需要你本人操作。\n\n如果你有自己的角色：把角色卡或一段描述一起给 AI，并在要求里说明"用我的角色，不要用示例的橘光"。AI 会按 `character/ROLE-TEMPLATE.md` 整理；只给一句话也行，它会按 `docs/CHARACTER-BUILDER.md` 先扩写、再确认。

## 从零搭一套（以 DSH + QQ 为例）

下面是我走过的顺序。每一步先跑通再往下走，后面出问题更容易定位。

**1. 底座**

装 DSH 桌面端和 Node.js（我用的是 20 以上），先确认 DSH 自己能正常建会话、能对话。模型和 provider 在 DSH 设置里配好，这一步跑不通就没必要继续。

**2. QQ 网关**

装 SnowLuma，登录机器人号，开 OneBot 的 HTTP 和 WS。日志里两个端口都 listening 之后，用 `get_login_info` 确认返回的是机器人账号。

这里容易出两个问题：WebUI 密码忘了（本机部署可以看 `scripts/snowluma-no-password-patch.ps1`，但只建议在本机用），以及多开 QQ 导致串号。机器人和个人号最好用不同的数据目录和端口，不然排查起来很麻烦。

**3. 接上 SurfCore**

配置里要填：DSH 地址、SnowLuma 地址和 token、机器人 QQ、允许的群和私聊。先在前台跑桥接，看日志确认三件事：连上网关、连上 DSH、发消息有回复。

如果 QQ 有消息但 AI 不回，先看白名单和 DSH 状态。如果收到两条一样的回复，通常是起了两个桥接进程，杀掉多余的再试。

**4. 角色卡和状态层**

把 [character/persona.md](./character/persona.md) 当骨架，内容换成自己的角色。结构先别动，改内容风险小一些。

状态层（心情、亲疏、最近关注的事）单独放一个文件，参考 `character/persona.daily.sample.md`。它只负责调语气和亲疏，不改人格设定，这样两边可以分开维护。

改完之后至少看两个指标：组合字数有没有超注入上限；抽几个常见场景，看回复还像不像这个角色。

**5. 稳定性**

SurfCore 自带基础的稳定性处理，日常够用。如果打算长时间挂机、同时跑多个群，可以把 [patches/](./patches/) 里的增量补丁打上——忙碌看门狗、重置补记、提交超时，主要给边界情况兜底。

验证方法比较直接：手动停一次 DSH 再恢复，看消息能不能接上、重置后还记不记得之前聊了什么。

**6. 再按需加东西**

发图、语音、跨群转述、B 站活跃都按需接，没有硬性要求。每项的接入方式、频率限制和常见问题，我在 [PLAYBOOK](./docs/PLAYBOOK.md) 里分节写了。这些功能依赖的接口和版本差异较大，以你环境里的日志为准。

## 可以按需改的地方

不用照单全收，按自己的情况挑。

- **人格**：性格的目的、软肋、说话节奏。改之前先想清楚新规则属于哪一层，不然容易越改越乱。
- **表达**：句数、语气词、网络词的浓度。用"句数/逗号数"这类硬指标，比写"尽量简短"可执行一些。
- **关系**：亲疏档位、撒娇和吃醋的边界。最好写清楚能做什么、不能做什么，"关系很好"这种描述模型不太好落地。
- **状态**：心情种类、刷新频率、亲疏变化。状态只调语气，别让它改人格。
- **语音**：发不发、什么时候发、原声还是合成。少而准比多而假好。
- **事务台**：跨群/跨私聊的整理转述。默认隐藏执行，敏感内容要拦，具体规则见协议文档。
- **平台**：QQ、B 站、网页可以共用同一套人格，表达浓度按平台调。

更细的改法、判断依据和排障步骤在 [PLAYBOOK](./docs/PLAYBOOK.md)。

## 已知限制

- 在 Windows + DSH + SurfCore 环境里验证过，其他系统需要自行适配。
- 补丁按当时的接口写，上游更新后需要手工对齐。
- 人格卡是示例，直接套到别的角色上效果会变；表达规则也需要按角色调。
- 参数和阈值是一组能跑的值，按环境再调。
- 偏重"怎么做"，原理推导较少。

发现错误或跑不通，欢迎开 issue 附版本和日志。
