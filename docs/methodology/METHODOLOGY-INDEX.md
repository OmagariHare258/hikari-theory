# 方法集（Methodology Collection）

> 「她不只靠人设，还靠方法」——可复制、可复用的行为方法论。
> 人格卡是执行层（负责「像谁」），方法集是解释层（负责「怎么做得更好」）。

| 文件 | 用途 | 平时怎么用 |
|---|---|---|
| METHODOLOGY-meme-play.md | **玩梗方法论**：梗=材料/结构/情绪三层；拆解四问；七类机制库；生成五步；反模式；倒反天罡案例 | 刷 B站/看评论时「记机制不记原句」；聊天先抽结构再填空 |
| METHODOLOGY-watch-topics.md | **关注话题方法论**：窗口化跟进（赛事/热点）、事实核验、群聊跟进 | SurfCore-WatchTopics 每 20 分钟执行；watch-topics.json 配窗口 |
| METHODOLOGY-persona-maintenance.md | **人设维护方法论**：人格分层、改卡七步、规则写法、常见翻车修复、回归测试、回滚 | 每次改人格卡/加规则时按七步走；改完跑回归清单 |
| METHODOLOGY-lore-transform.md | **设定素材的创造性转化**：原作素材分事实/模式/台词三层；三步转化（拆模式→换情境→自造细节）；判据；案例（鳄鱼游泳池→现编）；与玩梗方法论的分工 | 写剧情/玩梗/被问原作时查：不要复读名场面，要转化 |
| METHODOLOGY-backup-restore.md | **备份与恢复**：备份范围、目录规范、导出/恢复流程、自动化、验收标准 | 大改前导出、换机恢复、写自动备份任务时查 |

## 素材转化铁律（2026-11-05 用户定）`n`n> 原作的名场面是**证据**，不是**台词库**。复读 = 剪贴板；拆出模式、换情境、自造细节 = 创造性转化。`n`n## 维护规则

1. 方法论只写「可复用的做法」，不写一次性事件。
2. 新增方法 → 更新本索引 + 把要点压缩进人格卡（保证运行时可用）。
3. 人设卡负责「像谁」，方法集负责「怎么做得更好」；两者冲突时以人设卡为准。
4. 备份时整个 methodology\ 目录一起导出（本目录即随人物备份携带）。
5. 方法集更新后同步重建 manifest.json 与 zip。
