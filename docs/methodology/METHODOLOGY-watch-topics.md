# 方法论：时效话题的关注与跟进（Watch-Topics Playbook）

> 适用场景：让角色/机器人**对某件有时效性的事持续关注**，在正确的时间自己去查、在正确的地方说出来，而不是一直轮询、也不会漏。
> 本机参考实现：`%SURFCORE%\state\tools\watch-topic.ps1` + `state\watch-topics.json`（首个实例：KPL 北京WB）。

---

## 一、问题抽象

任何「关注一件事」的需求都能拆成 5 个问题：

| 问题 | 答错会怎样 |
|---|---|
| **什么时候查？** | 全天轮询浪费请求、查到旧闻、显得焦虑 |
| **怎么判断是新的？** | 把昨天的旧闻当今天的结果发出去 |
| **查到了放哪？** | 堆在脚本里，角色根本不知道 |
| **在哪说？** | 私聊的事发群里、群里的事发私聊，都很怪 |
| **说几次？** | 同一个结果刷屏、或者一次不说 |

方法论就是把这 5 个问题各自用一条**固定规则**回答，剩下的都是替换配置。

---

## 二、六条设计原则

1. **临近才查（Window Gate）**
   每个话题都带时间窗：`开赛前 30 分钟 ~ 结束`。窗口外脚本**直接退出，一个网络请求都不发**。
   窗口写在配置里，脚本启动先判时间——这是省时省事、也避免「提前瞎查」的第一道闸。

2. **只认当下（Date Filter + Dedupe）**
   - 结果必须命中**当天日期**（`M月d日` / `MM-dd` / `MM/dd`），否则不采信（防止旧闻冒充新结果）。
   - 用 `标题|URL` 做签名去重：同一条结果只处理一次（`lastSig`），跟进也只发一次（`lastFollowUp`）。

3. **就近跟进（Follow-up in Place）**
   结果出来后，扫描最近 2 天的 SnowLuma 日志：**哪些群/私聊聊过这个话题的关键词，就回哪里说一句**。
   规则：只发已配置的白名单群、每人/每群一条、不带 @ 全体、不超过一句。
   这一条让「跟进」自然变成**帮大家开话题**，而不是广播。

4. **不打扰（Quiet & Cap）**
   - 赛前提醒只发一次（`notified` 标记），并且只提前 `notifyBefore` 分钟。
   - 22:00~次日 08:00 不主动提醒。
   - 同一结果只跟进一次；窗口结束 6 小时后自动清理，避免堆积。

5. **只注入一行（Context Economy）**
   角色每轮只看一行「关注动态：<topic>：<标题>（时间）｜下一场：<时间 事项>」。
   不把正文、链接、长摘要塞进人格卡——省上下文，也避免她念材料。

6. **可演练、可降级（Dry-Run & Fallback）**
   - 脚本支持 `-DryRun`（只写日志不发消息）和 `-ForceWindow`（伪造窗口测试）。
   - 查询失败/查不到结果时**什么都不发**，人格卡规则是「查不到就说不知道」；数据源换了只改 `query` 与 `resultPattern`。

## 三、架构

```
watch-topics.json（配置：话题/关键词/窗口/查询词/过滤规则/跟进文案）
        │
        ▼
watch-topic.ps1（每 20 分钟由计划任务触发）
  1. 时间闸：不在窗口 → 退出（0 请求）
  2. 赛前提醒：窗口开始前 N 分钟 → /api/notify/owner 私聊管理员
  3. 查询：node web-query.mjs "<query>"  → 复用 DeepSeek 联网搜索（与 QQ 内 web_search 同源）
  4. 过滤：关键词命中 + 结果模式命中 + 当天日期
  5. 去重：lastSig 相同则跳过
  6. 落盘：latest → watch-latest.json
  7. 跟进：扫近 2 天日志找聊过关键词的群/私聊 → OneBot 发一句（同一结果仅一次）
        │
        ▼
affection.ps1（每小时）→ persona.daily.md 的「关注动态」一行 → 桥接每轮注入
```

## 四、配置字段（`state/watch-topics.json`）

```jsonc
{
  "topics": [
    {
      "id": "kpl-wb",                          // 唯一 id
      "label": "KPL 年度总决赛 · 北京WB",       // 展示名
      "keywords": ["北京WB", "WB"],             // 判定「聊的是这件事」+ 跟进目标扫描
      "query": "{keywords} 比赛结果",            // 喂给联网搜索的查询词（{keywords} 会替换）
      "windows": [                              // 时间窗（可多个）
        { "start": "2026-11-06 17:30", "end": "2026-11-06 23:30",
          "note": "胜者组决赛 vs 北京JDG", "notified": false }
      ],
      "todayDateRequired": true,                // 是否必须命中当天日期
      "resultPattern": "\\d+\\s*[:：\\-比]\\s*\\d+|胜|负|晋级|淘汰|夺冠|冠军|MVP",
      "notifyBefore": 40,                       // 赛前多少分钟提醒管理员
      "followUp": "北京WB刚刚有结果了——{title}。小光看完才来跟你们说的，押注的事回头再算。",
      "lastSig": "",                            // 运行时状态（脚本写）
      "lastFollowUp": "",
      "latest": null
    }
  ]
}
```

**新增一个话题 = 在 `topics` 数组里追加一个对象**，不需要写代码。

## 五、落地清单（7 步）

1. **定义话题与窗口**：这件事什么时候开始/结束？提前多久提醒合适？
2. **选查询词**：主体 + 结果类词（"XX 比赛结果" / "XX 发布会 时间" / "XX 官网 公告"）。
3. **定过滤规则**：哪些关键词必须出现、结果必须包含什么模式（比分/胜负/版本号/日期）。
4. **配置**：写进 `watch-topics.json`（或复制现有 topic 改）。
5. **测试**：
   ```powershell
   # 只写日志、不真的发消息
   pwsh -File ...\watch-topic.ps1 -DryRun -ForceWindow
   # 看日志
   Get-Content ...\state\watch-topics.log -Tail 20
   ```
6. **接入**：确认计划任务 `SurfCore-WatchTopics` 在跑（每 20 分钟，窗口外自动空转）。
7. **人设一句话**：人格卡第十四节已写「只在临近时关注 / 群聊跟进 / 查不到就说不确定」——新话题不需要改人格卡。

## 七、常见坑

| 坑 | 表现 | 对策 |
|---|---|---|
| 旧闻当新闻 | 比赛还没打就"发结果" | 必须命中当天日期；`todayDateRequired: true` |
| 重复刷屏 | 同一个结果反复发 | `lastSig` / `lastFollowUp` 双去重 |
| 提前打扰 | 中午就开始查晚上的比赛 | Window Gate：窗口外零请求 |
| 发错地方 | 私聊的事发群里 | 跟进目标按近 2 天日志的「话题出现地」决定 |
| 上下文膨胀 | 把结果全文塞进人格卡 | 只注入一行（标题截断 70 字） |
| 数据源挂了 | 脚本静默失败、假装没比赛 | 失败不猜、不编；日志留痕；人格卡要求"查不到说不知道" |
| 时区/日期格式 | 日期匹配不上 | 日期模式覆盖 `M月d日` / `MM-dd` / `MM/dd` |
| 测试发了真消息 | 群里被刷 | 一律 `-DryRun` 先跑 |

## 八、同款模板可复用的其他场景

| 场景 | query 示例 | 窗口 | resultPattern |
|---|---|---|---|
| 游戏版本更新公告 | `"XX游戏 版本更新 公告"` | 版本日前一天~当天 | `\d+\.\d+|更新|公告|维护` |
| 考试/报名/出分 | `"XX考试 报名 时间"` | 关键日期前 3 天 | `报名|截止|出分|成绩` |
| 发布会/新品 | `"XX 新品发布会 时间"` | 发布会前 2 小时~结束后 | `发布|售价|上市` |
| 追番/剧集更新 | `"XX 更新 时间 第X集"` | 更新日当天 | `第\d+集|更新|播出` |
| 快递物流 | `"XX快递 <单号>"` | 下单后每天一次 | `已签收|派送|到达` |

天气早报（`weather-scan.ps1` / `weather-report.ps1`）本质是同一模式的一个变体：
**订阅采集（关键词不同）→ 每日固定窗口发布（07:30）→ 按群订阅地点分发**。

---

## 九、一句话总结

> **把「关注」拆成时间窗 + 数据源 + 判定规则 + 去重 + 就近说出 + 一行注入；
> 只在临界的窗口里干活，只认当天的信息，只在聊过的地方开口，只用一行让角色知道。**

新需求来时先问：**窗口是什么？数据从哪查？怎么算新的？该在哪儿说？说几次？** —— 四问定完，剩下就是加一条配置。
