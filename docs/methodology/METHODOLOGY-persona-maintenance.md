# 人设维护方法论（Persona Maintenance Playbook）

> 目标：让「橘光」稳定地像她自己，而不是像一段被反复修补的 prompt。
> 核心原则：**角色设定第一 > 真人感第二**；人格卡是执行层，方法集是解释层。

---

## 一、结构：人格从哪来

| 文件 | 作用 | 生效方式 |
|---|---|---|
| `characters/<id>/persona.md` | 核心人设（分层：身份/说话/性格/关系/功能/沉浸） | 每条消息注入 |
| `characters/<id>/persona.daily.md` | 状态覆盖层（心情、亲疏、关注的事） | 每条消息注入，脚本自动生成 |
| `config.json` 的 `role.maxInjectChars` | 注入预算上限 | 改完需重启桥接 |

组合逻辑在 `src/persona-layers.js`（core + daily → 单段文本，超预算截断）。

---

## 二、改人格卡的七步流程

1. **定位问题**：从真实聊天截图里摘原句，写清"错在哪"（过度扮演？模板化？不贴人设？）。
2. **对照症状表**：查第四节「常见翻车与修复对照」，先定修复方向——没方向就动手，容易越改越花。
3. **改最小单元**：只动相关段落，别顺手重写整节。
4. **正例 + 反例成对写**：只写"不要 X"模型容易泛化错；给出「原句 → 改后」的对照。
5. **量化额度**：频率/次数/长度能写数字就写（"一场最多 1 次""每 10 条最多 1 次"）。
6. **检查长度**：跑 assemble 校验（见下），确认没截断；必要时调 `role.maxInjectChars` 并重启桥接。
7. **观察一条消息**：改完下一条回复即生效；用同一场景复测，不合格就回到第 1 步。

### 长度自检（Node）

```js
import fs from "node:fs";
import { composePersonaLayers } from "file:///%SURFCORE%/src/persona-layers.js";
const dir = "%USERPROFILE%/.dsh/surfcore/characters/char-mw0s7e4x";
const core = fs.readFileSync(dir + "/persona.md", "utf8");
const daily = fs.readFileSync(dir + "/persona.daily.md", "utf8");
const c = composePersonaLayers({ core, daily, personaMode: "full", mode: "v2", maxChars: 20000 });
console.log(c.chars, c.truncated);
```

> 超预算的处理顺序：**删重复 → 合并同类 → 降级为"稀有调料" → 最后才提高上限**。

## 三、规则怎么写才有效

| 写法 | 效果 |
|---|---|
| 「不要过度扮演」 | ❌ 太抽象，模型不知道边界 |
| 「聊技术/正事时零角色比喻（反例：服务器→换个大站台）」 | ✅ 有边界、有反例 |
| 「少用傲娇句式」 | ⚠️ 一般 |
| 「『才、才不是…呢』这类一天最多 1 次；被感动允许只说『哦』」 | ✅ 有额度、有替代方案 |
| 堆 20 条口癖 | ❌ 过度扮演 |
| 学语气不学台词（给判断法） | ✅ 可迁移 |

**规则优先级**（冲突时从上到下）：
1. 安全/边界（不伤人、不破次元、不违规）
2. 角色设定（像谁）
3. 真人感（像人）
4. 玩梗/趣味

**清理策略**：只加不删会越写越长 → 每加 3 条新规则，检查有没有可合并/过期的旧规则；人格卡保持在预算内、分层清晰。

## 四、常见翻车与修复对照

| 症状 | 根因 | 修复方向 |
|---|---|---|
| 把技术词翻译成设定词（服务器→站台） | 缺少"禁止名词替换"约束 | 正反例 + 判断句「我是不是把普通词换成了设定词？」 |
| 「才、才不是感动呢」 | 傲娇模板 | 给替代行为（沉默/只说"哦"/转移话题）+ 比例额度 |
| 每条都拖长音、自称小光 | 口癖过量 | 改成"偶尔"，明确频率 |
| 把设定科普给群友 | 缺"人设卡给自己看" | 不主动介绍/纠正，被认真问才短答 |
| 正事也撒娇/演 | 没分场景 | 「正事模式」段：先给结论，再回口味 |
| 撒娇要现实物品 | 没边界 | 撒娇落在可执行动作（发图/拍给我看） |
| 越聊越像通用 AI | 规则全是"不准" | 补「她就这么说话」的正面样例 |
| 每条都在给信息、只答不问 | 缺主动开口与零信息动作 | 见人格卡 3.2 / 3.5 / 4.6：一个念头一条、态度句合法、有料先爆 |
| 人格注入被截断 | 预算不足 | 组合校验 → 调 `maxInjectChars` → 重启桥接 |

## 五、回归测试清单（改完抽查）

- [ ] 正事提问：先说结论、没有设定比喻
- [ ] 被调戏：先配合，不真炸毛
- [ ] 被夸：反应具体、不套模板
- [ ] 群聊：不主动科普设定
- [ ] 玩梗：不解释、不连用
- [ ] 长回复：该拆条时拆了
- [ ] 闲聊：至少一条零信息回复（态度句 / 单张表情 / 复读对方原话）
- [ ] 主动：不等被问，先抛一条自己看到的、听说的
- [ ] 冷场：话掉地上不补、不总结
- [ ] 好感度/心情：表现与数值一致
- [ ] 跨会话：重启后人格仍在（读的是文件，不是内存）

## 六、回滚

- SurfCore 角色目录自带 `snapshots\`（自动/手动快照），出问题先回滚快照。
- 大改前先导出人物备份（见 `METHODOLOGY-backup-restore.md`）。
- 改坏了的最小回滚：`git`/文件历史里找回旧 `persona.md` 段落。
