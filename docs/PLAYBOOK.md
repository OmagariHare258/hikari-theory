# 实战手册（PLAYBOOK）

> 本章方法适用于任意角色。示例里的橘光只是参考样本，可以用 `character/ROLE-TEMPLATE.md` 换成自己的角色。

> 这是《橘小光理论》的"怎么做"部分：不解释原理，只给步骤、判据、故障处理。
> 适用：从零搭一个角色，或把已有角色改得"更像人、更稳、更能扩展"。
> 阅读提示：每一节都是「怎么做 → 怎么验证 → 出问题怎么办」；所有参数都是起点，不是标准答案。

## 1. 人格工程：从 0 到 1 捏一个角色

### 1.1 五步法

**第 1 步：写锚点（半小时）**
用三句话回答：
- 她是谁（身份/年龄/位置，一句话）
- 她遇到事的第一反应顺序（先「？」半拍 → 判断对方是谁 → 按关系给反应）
- 三条底线（不跳出角色、正事不装傻、不主动科普设定）

**第 2 步：写 8–12 条场景反应（最重要）**
格式：`场景 → 她的反应（一句示例）`。优先覆盖：
被叫住 / 被夸 / 被逗 / 被起外号 / 被求助 / 被冒犯 / 陌生人打听隐私 / 被问"你是不是 AI" / 要说再见。
> 示例比形容词有效 10 倍。写得出来，模型才演得出来。

**第 3 步：给每条性格配"目的"**
不要写"她调皮"，写"她调皮是想被注意；被无视会闹，但看到别人真难受会停"。
目的决定分寸；没有目的的性格会被模型演成刻板印象。

**第 4 步：加"不完美"**
选 5–8 个软肋：怕疼/怕牙医/路痴/挑食/被夸会飘/拖延/偶尔用错词。
原则：允许出糗，出糗不解释、不找补（找补就像 AI 在救场）。

**第 5 步：加"状态层"（单独文件）**
只写：当前心情、对谁亲疏、正在关注的事；并注明"只调语气，不改人格"。
状态层由脚本/人工刷新，不写进人格卡正文。

### 1.2 验证
- 找 10 个陌生场景问自己：她的第一反应能写出来吗？写不出来 = 卡不够。
- 连续聊 20 轮：有没有出现"通用温柔 AI"句式？有 = 表达规则不够硬。

### 1.3 出问题怎么办
| 症状 | 先查 | 处理 |
|---|---|---|
| 满嘴设定名词 | 是否把名词当"风格" | 名词降为稀有调料；技术/正事零比喻 |
| 像客服/AI | 是否有禁用词清单 | 加"禁用句式 + 替代表达"；答完就停 |
| 每句都傲娇/卖萌 | 是否只写了标签没写目的 | 改写成"行为+目的"；给频率上限 |
| 没有身体感 | 是否只有对话没有状态 | 加时间感/环境感/小欲望（少量、自然） |
| 一重置就换人 | 是否有补记/状态层 | 见 §8 无损重置 |

## 2. 人格维护：改卡不翻车

### 2.1 改卡七步
1. **定位层**：新规则属于哪一层（身份/内在/表达/关系/场景/能力/素材/状态）？
2. **查重**：同一主题是否已有表述？有 → 改旧的，不新增。
3. **写行为**：不写"禁止 X"，写"遇到 X 时怎么做"。
4. **配示例**：至少 1 条原句 → 她的话。
5. **控预算**：组合字数 ≤ 注入上限（留 10% 余量）。
6. **跑回归**：抽 5 个场景看是否仍像她、是否出现模板句。
7. **留回滚**：改前备份人格卡；改坏了能退回。

### 2.2 单一权威出处
一个主题只保留**一处**完整表述（其余位置引用行为，不复述规则）。
例：尾巴只在"身体边界"写一次；傲娇只在"关系/被逗"写一次；其他地方不再重复。

### 2.3 常见翻车
| 症状 | 原因 | 处理 |
|---|---|---|
| 越改越不像 | 多主题规则互相打架 | 按层拆开；删重复；一次只改一层 |
| 规则写了没用 | 抽象/无示例 | 改成场景速查 + 示例 |
| 模型抓错重点 | "禁止"式条目太多 | 删禁令，改行为替代 |
| 字数超限被截断 | 只加不减 | 合并同类项；示例挑最典型的 |

## 3. 表达工程：短、活、不像 AI

### 3.1 三个硬指标
- **句数锁**：闲聊 1–2 句；正事分条。
- **逗号锁**：闲聊单句不超过 1 个逗号（可按角色微调）。
- **拆条规则**：有转折/顺承就拆 2–3 条发；一条一个意思。

### 3.2 去 AI 腔清单
**禁用**：希望有帮助 / 如需进一步 / 我先说明 / 这部分我没考虑到 / 我认 / 总结一下 / 首先其次 / 作为 AI。
**替代表达**：直接给结论、带一句角色口吻、答完就停。

### 3.3 工具转译
查完/看完东西：用角色的话说结果，不播报"已为您查询到"；数字要准，语气照旧。

### 3.4 出问题怎么办
- 回复太长：先加"句数/逗号硬锁"，再删"总结/升华"倾向。
- 回复太冷：加语气词（啊/呀/啦/嘛/呢/——）与 1–2 条示例；别用"客服式礼貌"。
- 模型自带口癖：把口癖原文写进禁用清单，给 2 条替代表达。

## 4. 关系与状态：亲疏、心情、记忆

### 4.1 设计原则
- **人格卡**写"怎么用状态"，**状态文件**写"当前状态"。
- 状态只覆盖：语气、话量、主动程度、亲疏分寸；不改身份/价值观/说话风格。
- 聊天里**永远不主动报数值**；被问就嘴硬/含糊。

### 4.2 亲疏档位（示例，非标准）
冷淡 → 眼熟 → 朋友 → 亲近 → 最喜欢：
- 低档：短、平、不主动；
- 中档：会搭话、会吐槽；
- 高档：会撒娇/吃醋，但嘴硬；
- 陌生人：礼貌 + 距离，不装熟。

### 4.3 心情
- 3–6 种；强度 1–3；定时刷新。
- 影响语气与话量，**不影响正事质量**。
- 不主动说"我现在心情 X"。

### 4.4 记忆与重置
- 近期：最近 N 条消息 + 收尾摘要。
- 中期：活跃话题、对某人的印象。
- 长期：重要事件/关系里程碑（可放状态层或独立记忆文件）。
- 重置：写"补记"→ 下次唤醒注入一次 → 删除；细节记不清属正常，别自曝"上下文丢了"。

### 4.5 出问题怎么办
- 态度忽冷忽热：检查是否没读状态，或状态刷新太频繁。
- 对谁都一样热情：状态/亲疏没接入，或人格卡没有档位。
- 重置后关系断裂：补记内容太少；把"重要关系事件"写进长期记忆。

## 5. 工具：表情、图片、搜索

### 5.1 表情包
- 用前先列表情库挑最贴的；一条只发一张，不刷屏。
- 有"被逗/得意/无语"等情绪点再用，别每轮都发。
- 收藏：按对话气氛收，不按图判断（看不到图就别装懂）。

### 5.2 发图片（如"看照片"）
- **不要用表情包顶替照片**。
- 流程：搜"角色名 立绘/壁纸" → 取图片直链/页面 → 发 1–2 张 → 配一句角色的话。
- 找不到就直说，不搜真人、不搜低俗图、不刷屏。

### 5.3 搜索
- 时效性内容先查再答；交叉两个来源；查不到直说。
- 输出用自己的话说重点，不整段念结果。

### 5.4 出问题怎么办
- 发图失败：检查图片直链/大小/格式（PNG/JPEG/GIF/WebP）；页面图取 og:image。
- 表情发错/不贴：语义标签没维护；定期巡检并补标注。

## 6. 语音：什么时候用、怎么不烦人

> 这里只讲"使用策略"；具体 TTS/语音库接入属于插件能力，按你选的方案来。

### 6.1 原则
- 语音是**强表达**，不是日常默认；不确定就打字。
- 一条一句话（30–60 字，最多 120 字）；说完可补一句文字。
- 原声/语音库 > 现场合成（更像本人，延迟也更低）。
- 频率：每 8–10 条回复最多 1 条；一小时 2–3 条；同一次聊天不连发。

### 6.2 适合 vs 不适合
| 适合 | 不适合 |
|---|---|
| 晚安/早安、哄人、撒娇、重要的话 | 对方在开会/上课/上班 |
| 文字说不清的语气（得意、小声嘟囔） | 群里人多、正在争论正事 |
| 对方明显懒得打字 | 对方刚发来一大段要认真看的内容 |

### 6.3 出问题怎么办
- 太机械：检查断句参数（按句号分段，别按每个标点切）；适当放慢语速。
- 延迟高：短句优先；预热引擎；非实时场景可接受。
- 声音不像：换参考音/原声库；别用不同角色的声音混用。

## 7. 跨会话事务台：能力与边界

### 7.1 什么时候需要
- 用户让你"把 A 群聊的整理一下发我"；
- 需要跨群/跨私聊转述、汇总；
- 不需要把"过程"暴露在聊天里。

### 7.2 怎么做（用户视角）
1. 你在任意群/私聊提出任务；
2. 角色在后台开一个隐藏事务台：只能读指定会话、只能发指定目标；
3. 完成后：实际内容按你的要求发出；过程不显示、不打断对话。

### 7.3 边界（建议默认值）
- 读 ≤5 会话、发 ≤3 目标、单任务 ≤10 条、10 分钟超时；
- 敏感信息（手机号/证件/地址/密码/令牌）拦截；
- 该不该帮由角色按隐私/关系自审；拿不准就拒绝并说明。
- 称呼：内部显示「群名（群号）」；对外只用群名/昵称，不念编号。

### 7.4 好友之间的转发\n\n在自己私聊里把内容转给另一个好友，需要开 `allow.friendTargets`（默认关闭），细节见 [FRIEND-FORWARD.md](./FRIEND-FORWARD.md)。\n\n### 7.5 出问题怎么办
- 工具全部"令牌不对"：鉴权中间件不认识事务台 token → 放行事务台 token（handler 内仍校验 key+token）。
- 结果没出现在聊天里：默认 `reportToChat=false`，只发实际内容；需要摘要才打开。
- 前端多出会话：默认结束即归档；若保留，设 `keepSessionMs=0`。
- 发错目标/越权：检查任务的 sendTargets 与白名单；事务台只认列表内目标。

## 8. 运行与自愈：保命优先

> 说明：SurfCore 本身已经处理了大部分会话与发送稳定性；下面这些是长跑/多群场景下可以补的增量措施。

### 8.1 三层防线
1. **应用层**：桥接看门狗（忙 >5 分钟自动重置 + 写补记）。
2. **协议层**：唤醒租约 10 分钟、回合租约 8 分钟、提交超时 90/120 秒。
3. **进程层**：单实例守卫 + 幂等启动脚本 + 账号守卫（预期 UIN）。

### 8.2 监控什么（够用就好）
- 桥接/网关/DSH 三个连接状态；
- 每会话是否长时间"忙"；
- 发送失败率、重置次数、补记是否被消费；
- 日志关键字：繁忙、断线、超时、403、-352。

### 8.3 出问题怎么办（速查）
| 症状 | 先查 | 处理 |
|---|---|---|
| 某会话不理人 | 日志是否"会话繁忙"、忙了多久 | 等看门狗（5 分钟）或手动重置；检查是否事件丢失 |
| 重置后失忆 | 补记文件是否写入/注入 | 检查补记开关与注入逻辑 |
| 回复重复 | 是否跑了两个桥接 | 杀重复进程，启动脚本加幂等 |
| 网关掉线 | QQ 是否在线、hook 是否挂上 | 重启网关；确认账号 UIN 正确 |
| 发不出消息 | OneBot 返回码、好友/临时会话限制 | 群临时会话要带 group_id；非好友私聊可能被 QQ 限制 |
| B站接口 403/-352 | 请求频率/凭据 | 降频 + 抖动 + 退避重试；必要时重新登录 |

## 9. 最小架构：不接 QQ 也能玩

如果你只想做一个网页/本地陪伴角色：
1. 保留：人格卡（0–3 层）+ 状态层 + 表达规则；
2. 去掉：网关、桥接、QQ 工具；
3. 用任意前端（网页/本地 app）把"用户输入 + 角色卡 + 状态层"拼成 prompt；
4. 想加语音/图片：接任意 TTS/图床 API，按 §6/§5 的策略使用。

> 这套理论的核心（人格分层、表达约束、状态覆盖、素材转化）与平台无关。

## 10. 自定义方向清单

| 方向 | 可调项 | 建议 |
|---|---|---|
| 人格深度 | 性格目的/对冲/软肋/成长线 | 先稳 3 个核心特质，再加层次 |
| 表达浓度 | 句数/语气词/网络词/碎碎念 | 每类改动一次只动一个变量 |
| 关系尺度 | 亲疏档位/吃醋/撒娇边界 | 写清"能做什么/不能做什么" |
| 记忆 | 短期/长期/关系里程碑 | 重要事件单独存，别塞进人格卡 |
| 语音 | 时机/频率/原声比例/语速断句 | 先做"少而准"，再谈拟真 |
| 互动节奏 | 主动搭话/回复延迟/连发 | 用"每 N 条/每小时"硬上限 |
| 平台 | QQ/B站/网页语域浓度 | 同一人格，表达随平台调 |
| 多角色 | 共享世界观/独立状态层 | 状态隔离，人格可复用骨架 |

## 11. 故障速查表（综合）

| 症状 | 最可能原因 | 处理顺序 |
|---|---|---|
| 启动后无响应 | 底座没起/端口错 | 1) DSH 2) 网关 3) 桥接 4) 配置 |
| 消息进不来 | 网关没 hook/账号错 | 查 QQ 在线 + hook 日志 + UIN |
| AI 不回 | 会话被过滤/DSH 忙/模型未配 | 查白名单、忙标记、模型设置 |
| 回复质量差 | 人格卡太抽象/示例少 | 加场景+示例；去掉"禁止"堆砌 |
| 说话像客服 | 缺禁用词/长句多 | 加禁用清单 + 句数硬锁 |
| 语音难听 | 断句/音色/语速 | 按句号切、换参考音、降速 |
| 发图失败 | URL/格式/大小 | 换直链；只收 PNG/JPEG/GIF/WebP |
| 跨会话报令牌错 | 鉴权不认临时 token | 放行事务台 token；handler 校验 |
| 事务台出现在前端 | 会话被命名/保留 | `keepSessionMs=0`；不命名空白会话 |
| B站 -352 | 频率风控 | 降频+抖动+退避重试 |
| 双回复/串号 | 多实例/多账号 | 单实例 + 账号守卫 + 端口隔离 |

## 12. 验收清单（上线前逐项打勾）

- [ ] 人格卡：九层齐全；组合字数 ≤ 上限；关键条目（禁用词/示例/状态读法）都在
- [ ] 表达：闲聊 1–2 句；转折会拆条；无客服腔
- [ ] 状态：能读出心情/亲疏；不报数值
- [ ] 关系：陌生人/熟人/亲近三档反应有差异
- [ ] 工具：发图/表情/搜索至少一项可用，且不会刷屏
- [ ] 语音（如启用）：频率有上限；不适合场景会转文字
- [ ] 事务台（如启用）：隐藏执行；越权/敏感内容会拒绝
- [ ] 自愈：看门狗/补记/超时已开；重启后能恢复
- [ ] 运维：单实例；启动脚本幂等；日志能定位问题
- [ ] 合规：不冒充真人、不泄露隐私、不绕过平台风控

## 结语

**人格工程的核心是设计一个能长期稳定运行的"人"；卡写得长不长，关系不大。**

遇到问题时，按这个顺序想：
1. 这是人格问题、表达问题，还是工程问题？
2. 它属于哪一层？改那一层，别到处打补丁。
3. 改完能不能验证？不能验证的规则，先别加。
