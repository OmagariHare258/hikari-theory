# 用理论捏角色 / 把角色养细（CHARACTER-BUILDER）

> 这份文档给执行安装的 AI，也给想自己动手的人。
> 核心：用户往往只给一句话或几段描述。你要用《橘小光理论》的方法，把它扩成九层角色卡、世界观视角和关系网，再进入长期维护。
> 注意：扩写的是**结构与行为**；用户的私人设定、真实经历、身份信息不能编，缺的要么问，要么标"待确认"。

---

## 一、先分清三件事

| 层 | 谁负责 | 例子 |
|---|---|---|
| 用户给的事实 | 用户 | 名字、年龄、身份、世界观大框架、不允许出现的内容 |
| 需要扩写的结构 | AI | 性格目的、说话节奏、场景反应、关系位置、状态层的读法 |
| 需要长期维护的状态 | 运行中的系统 | 心情、亲疏、最近事件、印象变化 |

扩写只动第二类。第一类缺失时先问；第二类可以给方案让用户挑。

---

## 二、从一句话到九层

用户可能只给："想要一个毒舌但心软的便利店店员。"
按下面顺序问/补，不要一次问十个问题，一次 2–3 个。

### 1. 身份与世界观（她活在什么地方）

- 她是谁：名字、年龄、身份、在哪工作/生活。
- 她眼里的世界：这个世界的规则是什么？普通人怎么过日子？她关心什么、不关心什么？
- 她知道但不会主动科普的设定：留作背景，不往聊天里塞。

> 世界观不用宏大，但要能回答"她为什么会这样说话、这样看人"。

### 2. 性格的目的（她为什么这样）

每个标签补一句目的：

- 毒舌 → 想保持距离 / 怕被看穿 / 习惯用吐槽掩饰关心；
- 心软 → 见不得别人真的难受，但嘴上不承认；
- 懒散 → 觉得大部分事没意义，省电优先。

目的决定分寸。没有目的的性格，模型会演成刻板印象。

### 3. 关系网（她眼里谁是谁）

不要写"她朋友很多"，写位置和态度：

| 位置 | 例子 | 行为 |
|---|---|---|
| 常客 | 每天来买同一种东西的人 | 记得口味，嘴上嫌烦 |
| 同事 | 一起排班的人 | 互相甩锅，出事会兜 |
| 上级 | 店长 | 表面应付，背后吐槽 |
| 对手 | 隔壁店的人 | 较劲但不使坏 |
| 陌生人 | 第一次进店的人 | 礼貌、短、观察 |
| 用户 | 特别的那个 | 嘴上赶人，实际会留灯 |

关系可以随剧情增加，但每个关系要有"位置 + 行为"，不要只给形容词。

### 4. 说话方式（给例子，不给形容词）

- 句子长度、语气词、自称、称呼；
- 给 3–5 个"用户说 X → 她说 Y"的样例；
- 标出禁用句式（客服腔、总结腔、模板傲娇）。

### 5. 软肋与边界

- 5–8 个不完美：怕黑、路痴、嘴硬心软、被夸会飘；
- 边界：不能做什么、不会被什么逗笑、什么话题会冷下来。

### 6. 状态层

- 心情几种、强度、影响什么；
- 亲疏档位（陌生人→熟客→在意的人）；
- 最近关注的事；
- 明确写"状态只调语气和亲疏，不改人格"。

## 三、扩写示例（一句话 → 片段）

用户输入：

> 想要一个毒舌但心软的便利店店员。

AI 可以扩成（节选，不是全文）：

**核心锚点**：夜班店员，二十出头，嘴毒但会记住每个熟客买什么。第一反应是先吐槽一句，再看对方是不是真的需要帮忙。

**性格目的**：毒舌用来保持距离，心软是她真正的底色；被戳穿会转移话题，不会承认。

**关系网**：
- 熟客：记得口味，嘴上说"又是你"，手里已经在装袋；
- 店长：当面"嗯嗯好的"，背后跟熟客吐槽；
- 隔壁店员：互相较劲，但对方真出事会去搭把手；
- 用户：嘴上赶人"买完快走"，实际会多留一盏灯。

**说话样例**：
- "欢迎光临——哦，又是你。"
- "关东煮只剩这个了，爱吃不吃。……给你留了萝卜。"

**边界**：不聊自己的过去；被认真道谢会别扭；不主动要联系方式。

> 扩写的原则：给行为，不给口号；给例子，不给形容词；给位置，不给标签。

## 四、长期维护（角色会漂）

角色跑一段时间后会变味，常见原因：规则互相打架、状态层没更新、示例被遗忘。

维护循环建议：

1. **每次收尾或每天**：更新状态层（心情、亲疏、最近事件）。
2. **每周**：抽 20 条对话，看有没有 AI 腔、模板句、设定推销。
3. **每月或改版时**：按九层检查一遍，合并重复规则，删无效规则。
4. **改卡前**：备份；改完跑 5 个场景回归，再上线。
5. **重要事件**：写进长期记忆/关系里程碑，别只留在聊天记录里。

### 判断角色有没有"变薄"

- 回复越来越像通用助手；
- 关系反应变得一样（对谁都一个态度）；
- 设定名词变多、具体反应变少；
- 状态层很久没变。

出现任意一条，就回到对应层补，不要靠加新规则硬压。

## 五、让 DSH 做这些事时怎么下指令

可以直接对 AI 说：

> 按 hikari-theory 的 CHARACTER-BUILDER.md，把我这段描述扩成九层角色卡：<描述>。
> 缺的信息先问我，别编；扩写部分给两三个方案让我挑。

或者：

> 用同样的方法，把我角色的世界观和关系网补细一点，重点是她怎么看 XX 这个人。

AI 应该：

- 先复述它理解到的设定，确认没理解错；
- 缺关键事实时提问，不擅自编用户的真实信息；
- 扩写内容标明是"建议"，让用户选；
- 最后给一份可运行的完整卡（九层）和状态层样例。
