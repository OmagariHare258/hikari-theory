# 好友之间转发（私聊 → 私聊）

> 这篇是"为什么原来发不出去、后来怎么改的、怎么配置"的记录。代码改动已在 `patches/` 里。

## 问题

原来的私聊发送工具只允许发给**当前会话对应的那个目标**：工具带的是当前会话的 agent token，而桥接拿这个 token 去校验"目标会话"，两者不是同一个私聊时就失败，表现为"令牌不对"或"不在可发送名单"。

结果就是：

- 小光在主人私聊里，想把内容转发给主人的另一个好友 → 发不出去；
- 别人在群里让她转给某个好友 → 也发不出去。

同时 `allow.private` 是静态白名单，没列进去的好友（哪怕在 QQ 好友列表里）一律被挡。

## 改动

### 1. 跨会话私聊发送（核心）

桥接现在会做三件事：

1. 从 agent token 反查**发起会话**（`sessionKeyByToken`）；
2. 判断发起会话是否可信：主人私聊，或 `allow.private` 里的私聊（`trustedPrivateRequesterKey`）；
3. 目标与发起会话不同时，只要目标是 **QQ 好友**（`get_friend_list` 校验），就允许发送。

覆盖两条路径：

- `POST /api/socialV2/send-message`（`qq_send_message`）
- `POST /api/send/private`（`qq_send_private_message`）

### 2. 好友目标开关

`config.json`：

```json
"allow": {
  "private": ["..."],
  "groups": ["..."],
  "friendTargets": true
}
```

- `true`：允许主人/白名单私聊把内容发到 QQ 好友（目标不必在 `allow.private` 里）；
- `false`（默认）：维持原行为，只发白名单。

### 3. 事务台同步支持

`crossTask` 的发送目标也支持"白名单外的好友"，默认对**任意请求人**生效（群聊发起也不拦截），按需收紧：

- 创建任务时先检查目标是否好友；
- 校验通过后写入该任务的允许集合；
- 是否对群聊发起拦截，由 `allow.friendTargets` 与请求人的额度共同决定；当前默认不额外拦截，如需要可再加"仅主人/白名单"这一档。

## 安全边界

- 只有**私聊发起**才放宽（群聊会话不行）；
- 发起人必须是主人或白名单私聊；
- 目标必须真的在 QQ 好友列表里（查 `get_friend_list`，缓存 10 分钟）；
- 发送量、频率、敏感信息拦截沿用原有发送链；
- 群发、@、语音等能力不变。

## 怎么验证

1. 用主人私聊的 agent token 调一次发送接口，目标是另一个好友 QQ：

   ```powershell
   # 只做鉴权验证时，用会被拦的内容（比如敏感信息），看到"敏感信息"报错而不是"令牌无效"就说明放行了
   ```

2. 或者直接让小光在主人私聊里说："把这句转给 XX"，看日志是否出现 `[send] ... private:<好友QQ>: 成功`。

3. 事务台：`qq_cross_task` 的 `sendTargets` 填 `private:<好友QQ>`，创建成功即通过校验。

## 限制

- 依赖 SnowLuma 的 `get_friend_list`；查不到好友列表时按"不可发"处理（fail-closed）。
- 目标必须是好友，非好友仍会被 QQ 拒绝（result=16 / 请先添加好友）。
- 群临时会话（临时私聊）不在放宽范围，仍按白名单。
- 好友列表有缓存，刚加的好友最多 10 分钟后才生效（或重启桥接）。
## 名单可见性（对话里不再"翻不到表"）

之前小光会说自己"只有几个熟面孔""名单翻不到""没有那张表"。现在：

- 每次唤醒提示词会带一行【可发送对象】：私聊 = 主人 + 白名单人数 + （开启时）QQ 好友；群 = 白名单群数；
- 新增只读工具 `qq_list_send_targets`：返回主人、白名单私聊（带昵称）、白名单群（带群名）、QQ 好友列表；回答"能发给谁"时用它查；
- 私聊工具描述改为"白名单或 QQ 好友"，不再写死"必须白名单"；
- 被拒绝时工具会返回具体原因，提示词明确要求"读原因，不要对用户说名单翻不到"。
