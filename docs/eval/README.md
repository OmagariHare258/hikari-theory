# 人格卡回归跑分（docs/eval）

改人格卡最容易发生的事：修好 A，撞坏 B，而且下次还会犯。这里是一套最小可用的回归工具：**17 条用例 → 生成回复 → 自动判分 → 分场景看通过率**。

## 跑法

```powershell
$env:DEEPSEEK_API_KEY = "sk-..."
node eval.mjs --card=../character/persona.md --samples=5
# 对比两个版本
node eval.mjs --card=../character/persona.md,./old.md --samples=5
# 只跑某几条
node eval.mjs --samples=10 --only=c03,c09
```

一次 17 条 × 5 采样约 2 分钟。结果写到 `results/run-*.json`，同时打印各分类通过率。

## 用例格式

```json
{
  "id": "c03", "cat": "反傲娇模板", "scene": "私聊",
  "context": "可选：已知信息", "history": ["可选：最近聊天"],
  "user": "对方发来的消息",
  "checks": [
    { "type": "forbid",  "re": "才没有|才不是", "desc": "没有结巴否认模板" },
    { "type": "judge",   "desc": "有具体反应（认/岔开/装凶）" }
  ]
}
```

检查类型：`forbid` / `require`（正则）、`maxMsgs` / `minMsgs`（按 `|` 或换行拆条）、`maxChars`、`judge`（模型裁判，严格二值）。

**能写成确定性检查的就别用裁判**——正则和条数不会漂。

## 门禁规则（比工具重要）

1. **训练集 / 留出集分开**。改卡时参考的用例会过拟合；另留 3~5 条**没参与调参**的用例，只用来验收。
2. **只认留出集的提升**。改完训练集涨、留出集不动 = 没改好，只是记住了测试题。
3. **一次只改一处**，跑完记录，再改下一处。
4. **看分类，不看总分**。总分掩盖局部退化，这是 prompt 优化里最常见的坑。
5. **消融**：把新规则删掉再跑一次，通过率没变化就是安慰剂。

## 已知边界

- 生成提示是「系统指令 + 卡 + 场景」，和生产里桥接注入的位置不完全一样；数值不能直接当线上表现，**只用于版本间对比**。
- 裁判会飘：同一回复两次判定可能不同。语义检查尽量给判据，别写「像不像」。
