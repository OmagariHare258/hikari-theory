# 多窗口感知（像真人同时挂着几个聊天）

目标：让小光不是「一个窗口一个脑子」，而是知道别的窗口也在发生事情。

## 当前实现（通知层，不是并行脑）

每个 QQ 会话仍然是一个独立 DSH session，但每次唤醒时，桥接会注入：

- **【其他窗口】**：除当前会话外，有未读的会话列表——群/私聊 + 未读数；主人私聊额外带一句最后消息摘要（≤30 字）。最多 5 个。
- **【小光记着的事】**：跨会话事实/约定（见 SHARED-MEMORY.md）。
- **【别的会话最近】**（仅主人私聊）：最近 24h 每个会话 2 条摘要，最多 6 个。

提示词规则：

> 【多窗口】你同时挂着几个窗口：先把当前窗口回完；别的窗口有新消息先记着，别在 A 群提 B 群；主人私聊优先，被 @ 的其次。需要看别的窗口全文，只有主人私聊能用 qq_read_conversation。

权限：

- 群聊只能看到「别的窗口 +N 条」，看不到内容；
- 主人私聊能看到摘要，也能用 `qq_read_conversation` 翻全文；
- 只读，不能替别的窗口发消息。

## 2026-11-21 新增

- **注意力优先级**：【其他窗口】按 主人私聊 > @/叫名字 > 其他私聊 > 群聊 排序；提示词同步写明。
- **忙时先记下**：`qq_defer_reply(delayMinutes, note?)`，1–120 分钟后自动唤醒再回；不再硬回。
- **多窗口批处理**：主人私聊里可用 `qq_send_to(targetKey, messages)` 一次回别的窗口；桥接每 5 分钟检查一次，若 ≥2 个窗口有未读且主人私聊空闲，就合并唤醒主人私聊（20 分钟最多一次，8–23 点）。
- 仍是「多个会话 + 通知层」，不是单 session 共享大脑；共享大脑方案见 `SHARED-MIND.md`。

## 和「真人在多个窗口」的差距

真人是一个脑子、多个窗口：注意力可以随时切，记得每个窗口的上下文。当前架构是「多个会话各自醒来 + 共享通知层」，好处是：

- 上下文隔离，不会把 A 群的聊天串进 B 群；
- 每个会话有独立 token、独立工具权限；
- 前缀缓存可复用。

代价是：她不能真正「同时」处理两个窗口，只能先回当前，再根据【其他窗口】决定要不要切。

## 可选：共享大脑模式（未实现）

把所有 QQ 会话收敛到一个 DSH session：

- 每次唤醒注入「当前窗口 + 其他窗口摘要 + 共享上下文」；
- 发送时按当前窗口的 agent token 路由；
- 好处：真正一个脑子，跨窗口记忆最连续；
- 代价：上下文会混、token 成本高、前缀缓存失效、不同窗口的工具权限要重新做隔离；群聊隐私风险更高。

目前不做，先把通知层跑稳；如果确实需要「一个脑子同时看多个窗口」，再单独设计共享 session 的路由与权限。

## 后续可加的真人人味

- 注意力优先级：@ > 私聊 > 群聊 > 主动分享；
- 延迟回复/忙碌状态：先记下，过一会儿再回；
- 多窗口批处理：一次醒来处理多个窗口的未读，而不是每个窗口各醒一次（省 token）。
## 2026-11-21 跨窗口统一化

- 每个窗口的唤醒提示注入【刚才】：最近 90 分钟别的窗口的活动；主人私聊可看内容，群聊只给次数。
- 主动私聊加 25 分钟冷却：刚在任何窗口聊过就不发「好无聊/在干嘛」。
- 目的机制的上下文也带【刚才】，避免私聊像换了一个人。
- 限制：仍是每窗口独立 session，历史不会完全合并；下一阶段是 B（核心+嘴）或单 session。
