# 每周调优（Weekly Tuning）

> 目标：每周一次，用数据回答「她这周的对话质量是变好还是变坏」，不做无依据的改卡。

## 模组组成

| 部件 | 位置 | 作用 |
|---|---|---|
| 周报统计 | `docs/eval/weekly-report.mjs` | 7 天消息量/字数/口癖/AI 句式命中率 → Markdown |
| 风格对比 | `docs/eval/style-fidelity.mjs` | 小光 vs 群友：字数/标点/问号/自称 |
| 逐条扫描 | `docs/eval/aigc-watch.mjs` | 增量扫真实发送记录，定位具体句子 |
| 回归门禁 | `docs/eval/eval.mjs` | 21 条用例，改卡前后对比 |
| 扫描器 | `docs/eval/aigc-scan.mjs` | 单条文本诊断；`--mode=deepseekese` 专扫鱼八股 |
| 案例库 | `docs/eval/FISH-BAGU-CASES.md` | 社区案例 + 小光版等价物（不是肥鱼） |
| 历史 | `surfcore/state/weekly-stats.jsonl` | 每周摘要，供下周对比 |

## 每周流程（约 10 分钟）

1. **统计**：`node hikari-theory/docs/eval/weekly-report.mjs --days=7`
1b. **风格对比**：`node hikari-theory/docs/eval/style-fidelity.mjs`，看中位字数、≤10 字占比、标点/条、问号占比是否接近群友（群友通常 6–10 字、标点很少、几乎不带问号）。
2. **定位**：`node hikari-theory/docs/eval/aigc-watch.mjs --last=1500`
3. **对比**：读 `weekly-stats.jsonl` 上一条，看五项指标变化
4. **判定**（只看三条硬线）：
   - AI 句式命中率 >3% → 要看具体句子
   - 口癖率（复读词+——？开头）>10% → 加限频
   - 平均字数连续两周上涨 → 查是不是开始写小作文
   - 风格项（新增）：中位字数 > 群友 2 倍、标点/条 >1.0、问号占比 >10% → 偏书面，查原句
   - 情绪化短回复：≤3 字/纯标点占比 >10% → 敷衍过多；<2% → 可能太端着
5. **联网查新**（每周必做，15 分钟）：
   - 搜最近一个月的 AI 写作特征更新（关键词：`AI tells 2026` / `去AI味 更新` / `模型口癖`）
   - 把候选写进 `docs/eval/ai-tells.md` 的核查记录
   - 对每条候选跑 `node docs/eval/tell-check.mjs --re="..."`，看自家语料命中数
   - 按四道关门判定（证据 / 可判 / 不冲突 / 预算），**过不了就明确写「不加入」和原因**
6. **改卡**（仅当触发硬线）：
   - 一次只改一处，改完跑 `eval.mjs`，留出集不掉才保留
   - 只改写法，不加新规则总数（先删再加）
7. **记录**：把本周指标与结论写进 `state/weekly-reports/`

## 角色适配（小光不是肥鱼）

社区案例默认按「大肥鱼」写（本鱼、报尾巴、鱼鳍）。小光是海兰德铁道学园 CCC 的橘光，**不能直接照搬**：

| 肥鱼版 | 小光版 |
|---|---|
| 本鱼是一条普通的鱼 | 小光只是海兰德一个普通学生 / 普通乘务员 |
| 作为一条鱼 | 作为 CCC 的一员 / 作为一列列车 |
| 报尾巴、鱼鳍卖萌 | 不主动卖萌身体设定 |
| 一条消息堆好几个鱼梗 | 一条消息堆 ≥3 个列车词；技术话题 ≥2 个 |

每周额外看两项：

- **列车词 / 条**：`列车|站台|检票|发车|乘务员|车厢|轨道|晚点|脱轨`
- **自称「小光」/ 条**

硬线：

- 列车词 / 条 **>0.3**（约每 3 条一次）→ 过度扮演，要查原句；
- 自称 / 条 **>1.2** → 第三人称过密。

## 判定原则

- **不加无根据的规则**：没有原句证据的改动一律不做。
- **指标正常就报「无异常」**：不为了显得在干活而造问题。
- **改动必须可回滚**：改卡前备份 `persona.md`（脚本已自动）。

## 自动化

每周日 20:00 由定时任务启动本流程，结果发到专用调优会话。
