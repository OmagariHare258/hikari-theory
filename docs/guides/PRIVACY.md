# 隐私处理（B 方案）

目标：主人的真实信息、电脑信息、别人提到的名字，不进入群聊、不跨窗口搬运、不写进共享记忆。

## 本地词表

`state/privacy.json`（只在本机，不提交仓库）：

```json
{
  "terms": ["真实姓名", "用户名", "学号", "学校名", "C:\\Users\\用户名"]
}
```

- 词表命中后，共享记忆/跨窗口摘要会替换成 `[已隐去]`；
- 发往**非主人私聊**的消息命中词表 → 直接拒绝 `PRIVACY_BLOCK`；
- 主人私聊可以看，但人格卡要求「不主动提、不替别人转述」。

## 通用模式

不依赖词表也能抓：

- Windows 用户路径：`C:\Users\...`
- 身份证：17 位 + 校验位
- 手机号：1[3-9] 开头 11 位
- 邮箱
- `学号：...`

## 三层处理

1. **写入层**：共享记忆、跨窗口摘要、注意力摘要里的个人信息替换成 `[已隐去]`；
2. **发送层**：群聊/好友私聊发送前扫描，命中就拒绝，并提示「去掉后再发」；
3. **提示层**：每轮注入【隐私】规则；人格卡 4.5 有「隐私不外提」。

## B 方案的额外规则

- 群摘要进 core 前先脱敏；
- 群成员私聊追问：先校验群成员身份，只读该群最近记录，只回私聊；
- 群聊事实不自动升级为全局事实；
- 跨窗口发送前同时过隐私检查 + 串群检查。

## 维护

- 加词：编辑 `state/privacy.json` 的 `terms`，重启桥接生效；
- 词表不要提交仓库；仓库只保留通用模式；
- 如果出现误拦，把命中词从词表移除或改用更长的词。

## 撤回状态

- 外部脚本撤回消息后调 \POST /api/socialV2/record-recall\（body: key, ok, count）；
- 桥接写入会话 \ecallEvents\，并在 2 小时内每轮注入【撤回状态】；
- 她看到成功就松口气，失败就直说没撤掉——不再自己编「撤不回来」。
