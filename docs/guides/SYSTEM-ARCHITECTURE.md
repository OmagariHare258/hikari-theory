# 系统架构与调用顺序

这套系统不是“一个模型 + 一堆插件”，而是分层的。每一层只有一个职责，调用顺序固定，避免部件互相抢话。

## 一、分层

```
QQ 客户端
  └─ SnowLuma（OneBot 网关，3000/3001；WebUI 5099）
       └─ SurfCore 桥接（3100）
            ├─ DSH（会话/模型/工具宿主）
            │    ├─ 核心状态会话（core，不映射 QQ）
            │    └─ 各窗口嘴（群/私聊各自的 DSH session）
            ├─ 记忆卡（长期记忆，90% 自动压缩）
            ├─ 共享记忆（跨会话事实/约定）
            ├─ 生活模拟（睡眠/吃饭/疲惫，只影响语气和速度）
            ├─ 隐私层（词表 + 通用模式）
            ├─ 注意力层（其他窗口未读、优先级、延迟回复、批处理）
            └─ 语音/发图/B站/事务台/管理工具
```

## 二、一次消息的调用顺序

```
收到消息
  → 规范化为 group:xxx / private:xxx
  → 白名单 / 黑名单 / 授权（agent token）检查
  → 唤醒决策：优先级、是否忙、生活状态（睡/吃/午休）
  → 组装上下文（固定顺序，见下）
  → 嘴（当前窗口的 DSH session）生成回复
  → 出口检查：隐私词表、敏感信息、跨窗口泄漏、频率/额度
  → 发送到 QQ
  → 记录 recentMessages / 共享记忆 / 活动时间线
  → 核心状态、生活状态按各自节奏刷新
```

## 三、上下文注入顺序（不可乱）

1. **角色/身份**：人格卡、身份、当前会话；
2. **其他窗口**：未读数；主人私聊可见摘要，群聊只给数量；
3. **刚才**：最近 90 分钟跨窗口活动；
4. **核心状态**：core 会话维护的“同一个你”；
5. **身体状态**：life-sim 的睡眠/吃饭/疲惫；
6. **状态优先级**：身体 > 核心 > 刚才/其他窗口；冲突时以前者为准；
7. **安全/边界**：隐私、双胞胎认人、撤回状态、管理工具提示；
8. **关系/记忆**：本群印象、人物共同记忆、共享记忆、连续性；
9. **语音**：语音状态/好感度门槛/语音原则。

动态块都有字数上限；人格卡和日层是固定底座，不参与临时拼接。

## 四、单一事实来源

| 数据 | 唯一写入方 | 读取方 |
|---|---|---|
| 人格卡 / 状态层 | 角色编辑器 | 所有窗口 |
| 记忆卡 | 记忆卡插件（宿主） | 所有窗口 |
| 共享记忆 | 桥接 / `qq_shared_append` | 所有窗口 |
| 核心状态 | core 会话 | 所有窗口、目的机制 |
| 生活状态 | `src/life-sim.js`（纯计算） | 所有窗口、主动机制 |
| 窗口消息 | 桥接 social-v2 | 对应窗口、注意力层 |
| 隐私词表 | 本机 `state/privacy.json` | 写入/发送/读取 |

没有第二个组件写同一份状态；core 不直接发 QQ，嘴不直接改 core 状态。

## 五、工具能力矩阵

| 能力 | 主人私聊 | 群聊 | 其他私聊 | core | 学习会话 |
|---|---|---|---|---|---|
| 当前窗口发文本/表情/语音 | ✅ | ✅ | ✅ | ❌ | ❌ |
| 发到别的窗口 | ✅ `qq_send_to` | ❌ | ❌ | ❌ | ❌ |
| 读别的窗口记录 | ✅ 全部 | ❌ | ❌ | ❌ | ❌ |
| 群内私聊同群成员 | — | ✅ 成员校验 + 限频 | — | ❌ | ❌ |
| 改人格卡（admin） | ✅ | ❌ | ❌ | ❌ | ❌ |
| 跨群事务台 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 本地 shell/文件 | ❌（QQ 预设不挂） | ❌ | ❌ | ❌ | ❌ |

边界由桥接路由强制，不靠提示词自觉。

## 六、启动顺序

1. QQ 客户端登录机器人号；
2. SnowLuma 启动（`hookAutoLoad=true`，启动文件夹 + `SnowLuma-Watch` 每 10 分钟兜底）；
3. SurfCore 桥接启动（3100），等 DSH；
4. DSH 启动，桥接建会话/核心会话；
5. 语音 `voxd` + GSV（8765/9880），`SurfCore-VoiceWatch` 兜底；
6. 记忆卡/生活模拟/核心状态按各自周期刷新。

任何一步失败，前面的层不阻塞后面的层；桥接会等待并降级。

## 七、总检

```powershell
node scripts/system-health.mjs
```

按「链路 → 角色/状态 → 安全 → 运维」检查端口、QQ 登录、TTS、核心状态、记忆卡容量、隐私词表、最近错误。

- 退出码 0：没有 FAIL；
- 退出码 1：有 FAIL；
- `--json` 输出机器可读结果。

## 八、故障处理原则

| 故障 | 处理 |
|---|---|
| SnowLuma 掉线 | 桥接等待重连，日志 5 分钟一条；`SnowLuma-Watch` 拉起 |
| TTS 挂了 | 先发语音库原声；语音看门狗拉起 GSV |
| 记忆卡 >90% | 自动压缩到 85%，归档到全量卡 |
| L3 重复工具错误 | 先查桥接路由拒绝原因，修边界，不让模型重试 |
| DSH 会话丢失 | 桥接自动重建会话；核心状态文件保留 |
| 核心状态过期 | 桥接 15 分钟刷新；嘴仍可用最近状态 |

原则：**状态只影响表达，不把状态播报给用户；工具只做被授权的事。**
